# Embedded solution player

`client.js`, `client.d.ts` and `protocol.js` are copied from `om-render/web-player/src/embed/`, using protocol version 1. The server-only command allowlist is omitted from the host copy. Keep these files and `tests/player-client.test.mjs` in sync when updating the player protocol; no sibling checkout is needed to build this project.

`GifViewer` fetches puzzle/solution bytes on the host and transfers copies to one persistent cross-origin iframe at the player site's root (`/`). Closing the dialog hides and pauses it instead of destroying the WebGPU context, atlas or WASM instance; reopening the same record seeks back to cycle 0, while another record is loaded through the existing client. Puzzle/solution bytes and confirmed author results are cached for the page session. The client checks origin, source window, protocol version, session and request IDs. Changing records or closing cancels pending downloads and Preview loads without disposing the player; late results cannot affect the next record's actions. Closing also cancels pending author lookups: reopening retries failures/cancellations, but reuses confirmed authors and confirmed unknown results. The client is disposed on failure or unmount.

Loads send only puzzle/solution files, title and autoplay. Collision detection is always enabled in the current player; `collisionDetection` and `replayAtVictory` load options and their read-only state are removed. Background analysis automatically selects continuous playback (with a certified safe-loop cache when available) or `0..@V` victory replay for solutions confirmed to halt/collide after victory or complete without ongoing material activity. Victory replay holds the final pose for one playback cycle before restarting; pause/zero speed freezes that hold and stepping can advance/rewind it. Failed or budget-limited analysis does not force replay; a live post-victory collision can still select it. Pre-victory collisions stop, and unfinished solutions do not replay early. The host consumes the current playback/analysis/cache state without choosing a strategy or adding a replay timer. Older deployed players may send extra state fields and remain connectable, but the automatic policy requires the matching current player build. The independent solution verifier is unchanged.

Local `solutionKey` still takes precedence over remote `solutionUrl`. Loaded-record and byte-cache keys must continue distinguishing local and remote sources: a local storage key can equal a remote URL while referring to different bytes. Switching sources reloads the solution, while reopening the same source reuses the warm simulation.

Configure the player origin with the Worker binding `PLAYER_ORIGIN` in `wrangler.jsonc` (default `https://om-player.pages.dev`), just like `LEADERBOARD_API`. Use `.dev.vars` for local overrides. The first playback fetches `/api/config` with `no-store`; the persistent player keeps that origin for the rest of the page session, so a binding change takes effect after reload. Only the public player origin is exposed. Individual `GifViewer` instances may override the complete player URL with the optional `playerUrl` prop.
