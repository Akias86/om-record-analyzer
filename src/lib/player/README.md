# Embedded solution player

`client.js`, `client.d.ts` and `protocol.js` are copied from `om-web-simulator` (`embed/client.*` and `src/embed/protocol.js`), using protocol version 1. The protocol import path is adjusted and the server-only command allowlist is omitted from the host copy. Keep these files and `tests/player-client.test.mjs` in sync when updating the player protocol; no sibling checkout is needed to build this project.

`GifViewer` fetches puzzle/solution bytes on the host and transfers copies to one persistent cross-origin `/player/` iframe. Closing the dialog hides and pauses it instead of destroying the WebGPU context, atlas or WASM instance; reopening the same record seeks back to cycle 0, while another record is loaded through the existing client. Puzzle/solution bytes and confirmed author results are cached for the page session. The client checks origin, source window, protocol version, session and request IDs. Changing records or closing cancels pending downloads and Preview loads without disposing the player; late results cannot affect the next record's actions. Closing also cancels pending author lookups: reopening retries failures/cancellations, but reuses confirmed authors and confirmed unknown results. The client is disposed on failure or unmount.

Configure the simulator origin with the Worker binding `PLAYER_ORIGIN` in `wrangler.jsonc` (default `https://omsim-web.pages.dev`), just like `LEADERBOARD_API`. Use `.dev.vars` for local overrides. The first playback fetches `/api/config` with `no-store`; the persistent player keeps that origin for the rest of the page session, so a binding change takes effect after reload. Only the public player origin is exposed. Individual `GifViewer` instances may override the complete player URL with the optional `playerUrl` prop.
